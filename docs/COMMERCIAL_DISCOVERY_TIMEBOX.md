# Commercial Discovery Timebox

Status: binding operating rule. Supersedes any governance framework, ledger or
workflow that predates it. If this document ever grows past one page, it has
become the disease it was written to cure.

## Why this exists

A previous commercial attempt capped spend at £210 and ran zero tests. Money was
gated; analysis was not. Every further investigation looked free, so the search
ran indefinitely at zero marginal cost to itself. Time was the largest
expenditure in the project and the only one nobody metered.

## The rule

Before any research begins, four numbers get written down. Research does not
start until they exist.

1. **Research budget.** A wall-clock limit. Default 3 hours.
2. **Pass criteria.** What must be true for a candidate to justify a paid test.
   Stated as a falsifiable threshold, not a vibe.
3. **Experiment cap.** Maximum spend on the resulting test. Default £210.
4. **Failure action.** Which search space we move to if nothing passes.

At the deadline exactly one of two things happens:

- A candidate clears the bar → run one simple manual experiment, capped at (3).
- Nothing clears the bar → **stop**. No spend. Move to the failure action.

The bar is frozen for the duration of the window. It cannot be relaxed to
manufacture a candidate, and it cannot be tightened to disqualify one. Both are
the same failure wearing different clothes.

"Ship the least-bad option at the deadline" is explicitly **not** the rule.
No candidate means no spend.

## Recursion cap

Changing the search space is also unbounded, so it gets its own limit: at most
three search spaces per commercial attempt. After the third failed window, the
whole attempt stops and goes back to the human for a strategy decision. Without
this, the timebox just moves the stall up one level.

## Clock ownership

The deadline is external — a real timer, set before the first search. Resuming
after a break does not reset it; the clock restarts where it stopped. Prior
research never buys additional research time.

## First transaction rule

Until a commercial lane has produced genuine external revenue, infrastructure is
presumed unnecessary.

Test for any proposed automation: *is this experiment impossible without it,
today?* If the automation merely makes a hypothetical future operation faster or
more scalable, it is banned. Build the factory after the first sale, not before.

## The actual next milestone

£1, not £210. One transaction where a stranger pays because of something we put
into the world, with £1 left after directly attributable cost. Then ask whether
it happens twice. Everything else is premature.

## Notes for any AI advisor operating under this rule

Recommending more research is never wrong in the moment; recommending "test
this" carries visible downside if it flops. That asymmetry, not incompetence, is
what produces endless validation gates. At the deadline, output a decision.
Precise arithmetic on assumed inputs is not evidence — if a number was invented,
label it as invented in the same sentence.
